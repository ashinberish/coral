# Coral API

FastAPI + PostgreSQL backend for Coral.

| Concern | Tech |
|---|---|
| Web | FastAPI (async), Pydantic v2 |
| Config | pydantic-settings (`CORAL_*` env vars, `.env` locally) |
| Database | PostgreSQL 18, SQLAlchemy 2.1 (async, asyncpg) |
| Migrations | Alembic (async env, naming conventions) |
| Observability | OpenTelemetry traces + metrics (OTLP), structlog JSON logs with trace correlation |
| Errors | RFC 9457 `application/problem+json` |
| Tooling | uv, ruff, mypy (strict), pytest |

## Layout

```
src/coral_api/
  main.py            app factory (create_app) + lifespan
  cli.py             `coral-api` entrypoint (uvicorn)
  core/              cross-cutting: config, logging, telemetry, errors, middleware
  db/                Base + naming conventions, session/engine, generic repository, model registry
  api/v1/            versioned public router
  modules/<feature>/ vertical slices: models, schemas, repository, (service, router)
migrations/          Alembic environment + versions
tests/unit           fast tests, no database
tests/integration    run against a real PostgreSQL
```

Modules own their models/schemas/repositories. Routers stay thin; business rules go in a
`service.py` per module. Every model must be imported in `db/models.py` so Alembic sees it.

## Run locally

```bash
docker compose -f ../../infra/docker/compose.yaml up -d   # postgres, otel collector, jaeger
cp .env.example .env
uv sync
uv run alembic upgrade head
uv run coral-api                                          # http://localhost:8000/docs
```

Traces: http://localhost:16686 (set `CORAL_TELEMETRY__ENABLED=true`).

## Deploy

Production runs on **Vercel** (Python function, Neon Postgres). Merges to `main` deploy
automatically via `.github/workflows/api-deploy.yml` (checks → migrations → deploy → smoke
test). Setup and policies: [docs/deploy/vercel.md](../../docs/deploy/vercel.md).
The Dockerfile remains for local use and other container hosts.

## Checks

```bash
uv run ruff check . && uv run ruff format --check .
uv run mypy
CORAL_DATABASE__NAME=coral_test uv run pytest   # integration tests need Postgres (skipped if unreachable)
```

## Migrations

```bash
uv run alembic revision --autogenerate -m "add something"
uv run alembic upgrade head
uv run alembic downgrade -1
```

Review every autogenerated migration before committing.

## Endpoints

| Path | Purpose |
|---|---|
| `GET /healthz` | Liveness |
| `GET /readyz` | Readiness (checks the database) |
| `GET /v1/meta` | Service name, version, environment |
| `POST /v1/auth/{apple,google}` | Sign in with a provider ID token → access + refresh tokens |
| `POST /v1/auth/refresh`, `/logout` | Rotate / revoke the session |
| `GET/PATCH/DELETE /v1/me` | Profile, goal, timezone; account deletion |
| `POST /v1/drinks` | Log a drink; idempotent on the client-supplied `id` (offline sync) |
| `GET /v1/drinks`, `GET /v1/days` | Logs / daily totals for a day range (`from_day`, `to_day`) |
| `DELETE /v1/drinks/{id}` | Delete a log (idempotent) |

Auth design and setup: [docs/auth.md](../../docs/auth.md). After changing endpoints, run
`make api-client` and commit the regenerated `packages/api-client`.
| `GET /docs` | OpenAPI UI (disabled in production) |
